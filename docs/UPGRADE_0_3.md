# Market Radar 0.3 升级说明

0.3 增加独立的「行情与信号」工作区，把有限自选列表的价格、成交量和历史规则事件与已保存资讯关联展示。原有关键词资讯、本人关注、推荐、来源状态、按需正文和中文阅读继续保留。启动命令不变：更新后执行 `./setup.sh` 安装依赖，再使用 `./start.sh` 或 `npm start`。

## 当前采集范围

| 市场 | 实际接入 | 周期与口径 |
| --- | --- | --- |
| 加密 | 固定 `data-api.binance.vision` 的原生公开 REST | Binance 现货 USDT 交易对，1h；保存原始 close time、服务器时间、base/quote volume 和交易笔数 |
| 美股、港股 | yfinance / Yahoo | 常规交易时段 1d；`auto_adjust=False`、`repair=False`、`actions=True`、`keepna=True`，保留来源返回的 OHLCV、分红、拆股与空值 |
| 沪深股票 | AKShare / 东方财富 | 1d，`adjust=""` 原始价格；成交量单位为手，非额外前后复权 |

初始自选为空，预设只是候选。打开页面和添加标的均不自动访问上游；点击刷新此标的或全部自选后才入队采集。最多 20 个标的，展示最多 180 根；股票每次读取最多 240 根，包含 60 根指标预热，加密读取 180 根并可复用既存历史预热。覆盖范围随来源和标的而异。当前没有 Futu/OpenD、券商账号、合约数据、WebSocket、回测、下单或全量历史分页回补。CCXT 是接口与设计参考，不是运行依赖。

美股/港股会校验 Yahoo 返回的资产类型、币种和交易时区：首版仅接受股票/ETF，美股 USD / America/New_York、港股 HKD / Asia/Hong_Kong；字段缺失或不匹配时拒绝保存，避免把加密或其他币种的代码误贴为股票行情。调用设置表示“不额外执行 yfinance 自动复权”，不能据此宣称 Yahoo 所有历史价格都是未经供应商处理的逐笔原始数据。公开库也不能保证实时、长期可用或所有证券覆盖；代码许可与数据用途条件分别适用。

## 质量、指标与历史事件

行情保存 provider、symbol、interval、币种、交易时区、成交量单位、adjustment、session、开闭边界、closed、received_at、quality 和 source_hash。不同来源或口径不拼成同一序列。缺失行原样保存；图表和指标不填零，不删除空值后压缩时间。

股票使用 exchange_calendars 的实际交易日历处理休市、半日市、夏令时及缺失交易日，收盘后另留 30 分钟缓冲；日历无法确认时保守保持未确认。Binance 先获取服务器时钟，再读取 K 线，使用原始 close time 保守确认闭合，避免由后取得的时钟误确认早先的盘中快照。新鲜度使用合格闭合 K 线比较最近已结束小时或交易日，缺失或无效末行不会把旧信号标成最新；HTTP 接收时间只表示获取时间。

TA-Lib / NumPy 计算 MA20、MA60、RSI14 和量比，并使用实际 lookback 检查预热。默认正式规则是 20 根区间突破、MA20/MA60 穿越及相对此前 20 根均量的两倍放量。RSI14 阈值穿越规则默认关闭，纯计算入口支持显式选择；当前 UI 不提供规则启停配置。

未闭合、缺失、无效、口径变化或样本不足时跳过正式事件。缺口及可识别拆股/分红重新开始预热，避免原始价格跨公司事件产生伪信号。沪深原始日线无法提供完整公司事件时，异常大幅价格变化保守标记，不能声称已经完整处理所有复权事件。事件保留规则版本、参数、数值证据、行情来源、确认与生成时间，默认返回最近 20 条历史事件；数量不是收益或有效性评分。

内部计算最多使用 240 根，图表仍显示最多 180 根。股票预热的 60 根与展示窗口一起重新读取，避免供应商在拆股等事件后修订历史价格，却与旧价格缓存拼接。存储会核对新旧窗口接缝及缺日补齐后的后继行，将缺口、清除与哈希变化持久保存。窗口右移导致的前置样本不足不会被当作来源修订而误撤回旧事件。价格、公司事件或质量事实改变会记录行情和信号修订；在可判断窗口内撤回已失效事件，旧事件样本不足时标记待重验。来源失败或数据未确认新鲜时，保留旧图并明确历史状态，不能视为本次新触发。

## 独立持久化与任务

行情保存在数据目录的 `market-radar-market.sqlite3`，资讯仍使用 `market-radar.sqlite3`。独立库持久保存自选、K 线、质量、规则事件、修订和任务；删除自选会移除其行情及事件。无需清空新闻数据库。

一个独立本地 worker 执行耐久队列，相同活动刷新请求复用已有任务。进程重启后恢复中断请求，已完成标的不重复采集；各标的独立显示状态，一个失败仍可保存其他成功结果。公开请求有来源检查、限速和有限重试；股票 SDK 在可终止进程中运行，单标的和整个任务都有时间预算。此恢复模型针对本地单后端进程，不是分布式调度系统。

更新依赖后保持原启动方式。停止服务后备份整个数据目录，保留两个数据库、WAL 文件与本机会话加密密钥；当前版本没有将真实个人 X/Reddit 账号纳入开发验证。

## 与资讯和中文阅读的连接

同期资讯从现有资讯库筛选，不新增后台新闻请求。使用固定公司别名或明确代码词边界，避免仅凭 `000001` 这样的裸数字关联；最多返回 8 条，并显示最新 K 线结束时间前 3 日到后 1 日的时间窗口。相关资讯保留完整已有 Post、原链接、原文 hash 和译文，支持沿用一键中文模式与原文入口；“搜索相关资讯”返回资讯工作区并填入查询，由用户继续发起搜索。同期实体匹配是研究线索，不是新闻造成价格变化的证明。

新增 API 前缀 `/api/market`：总览、自选增删、手动刷新、任务状态及标的快照。读取总览或快照只读取本机已保存数据，不自动采集上游行情。

## 本轮验证

根代理在隔离服务中通过实际行情 API 取得以下样本，没有登录券商或个人社交账号，也没有将该测试数据覆盖到原资讯库。

| 实际样本 | 保存与闭合/质量结果 | 返回的历史规则事件 |
| --- | --- | --- |
| BTC/USDT，1h | 180 根；179 闭合、1 未闭合 | 20 条，受展示上限限制 |
| AAPL，1d | 180 根；公司事件标记，含 1 未闭合行 | 20 条，受展示上限限制 |
| 0700.HK，1d | 180 根；1 行缺失 OHLCV及公司事件；末行阻断计算，可用闭合数据过期时标记历史 | 5 条历史事件 |
| 600519.SS，1d | 180 根；该窗口没有质量标记 | 11 条历史事件 |

这些结果说明此网络、版本与时间点的四个有限窗口成功；不证明全部标的、长期稳定性、完整历史、实时权限或规则收益。先前研究中的未带完整参数的东方财富原始 GET 失败，属于另一次历史探测，不能替代本次 AKShare 服务结果。

最终 `npm test`：后端 **234 项通过**、前端 **4 项通过**；TypeScript 和生产构建通过。后端有 216 条依赖弃用提示，Node 有 Type Stripping 实验提示。正式启动及重启成功；桌面 1440×960、手机 390×844、深色模式、错误恢复、质量说明与资讯搜索入口均通过浏览器检查，无运行异常或横向溢出。

原资讯库与升级前备份逐表逐行相同，170 条资讯、60 条译文及收藏/已读标记保留；两个数据库完整性均为 `ok`。实际页面的 8 条相关资讯可复用 DeepSeek Flash 缓存译文；当前启动环境未检测到 `DEEPSEEK_API_KEY`，本轮没有重新调用模型，新内容翻译需要补充环境或项目 `.env` 后重启。模拟首次详情读取失败和未缓存翻译仅修改浏览器响应，不写入数据库。最终记录见 [TESTING.md](TESTING.md)。

**0.2 的历史验证保持原义**：`黄金 OR 美联储` 收到 47 条、新增 33 条，重复运行新增 0 条；当时原 137 条资讯和 60 条翻译记录保留。它不是本轮 0.3 迁移的数据计数，详情保留在 [UPGRADE_0_2.md](UPGRADE_0_2.md)。
